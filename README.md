# 校园汇 · 学生端校园服务网站

这是一个**面向学生使用的校园服务产品前端**，不是融资路演页。当前是无后端的可运行体验版：校园介绍、校园论坛、校园活动、校园墙、跑腿需求、闲置商品、通知和个人中心均已提供产品界面与基础交互；演示操作保存到当前浏览器，不会产生真实认证、订单、联系或支付。

## 项目结构

```text
campus-hui/
├── index.html     页面外壳、导航、搜索、弹窗和静态资源入口
├── style.css      产品界面、状态样式与响应式布局
├── content.js     独立的校园资料、作业/活动待办、动态、需求、商品、通知和论坛数据
├── api.js         数据访问适配器：本地演示存储 / 可配置的服务端 API
├── script.js      页面路由、表单、筛选、收藏、演示操作与提示
└── README.md      本地运行与后端接入说明
```

所有页面示例数据集中维护于 `content.js`，由 `index.html` 在 `api.js` 和 `script.js` 之前加载。页面数据不散落在页面模板中；想替换校园名称、文案或种子内容，可以直接编辑该数据文件。

## 运行

可以直接在现代浏览器打开 `index.html`，也可以在项目目录运行静态服务器：

```bash
python -m http.server 8000
```

访问 <http://localhost:8000>。无需 Node、框架、安装依赖、数据库或构建步骤。

## 已实现的体验

- 校园首页：先介绍校园，再以随机顺序混排校园讨论和校园活动卡片；主页不再单设校园服务模块。
- 主页动态卡片会随机变化排列及占位尺寸；卡片高度限定在桌面 190–300px、移动端 170–250px。
- 作业 / 活动待办栏：默认显示，可从侧栏隐藏；作业状态和展示偏好保存在当前浏览器。
- 用户资料：点击用户头像后在右侧打开；首页摘要只展示学校、学院和班级等校园级信息。
- 校园墙：分类筛选、搜索、发布动态、喜欢状态，以及个人发布管理和演示消息列表。
- 校内跑腿：分类浏览、发布需求、本地演示接单状态，以及个人任务和消息列表。
- 二手集市：分类浏览、商品搜索、发布闲置、收藏，以及个人发布、收藏和消息列表。
- 通知公告：公告列表与本地已读状态。
- 校园论坛：作为校园首页内容区，可在首页浏览讨论并发起话题；旧论坛地址会打开首页论坛区。
- 个人中心：活动记录、收藏与本地认证流程体验。
- 黑白为主的配色、更易读的文字尺度；桌面导航默认展开并可折叠，收起时悬浮/聚焦可临时展开、点击导航项可固定展开；移动端保留菜单抽屉。
- 作业与活动待办默认在右侧抽屉中展示，可通过顶部/侧栏入口、关闭按钮、遮罩或 Escape 收起；搜索支持 `Ctrl/⌘ + K` 聚焦。

## 本地演示与真实业务的边界

- 当前“示例大学”、学生、动态、商品、通知及校园活动均为虚构示例。
- “身份认证”只切换浏览器里的演示状态；没有学信网、学校统一身份认证或人工审核连接。
- “接单”只在浏览器记录演示状态；没有通知他人、真实履约、支付或退款。
- “聊聊”和评论显示暂未接入说明；不会联系真实卖家或发送评论。
- `content.js` 的用户数据仅用于界面体验。正式上线前需要替换为真实授权来源和合规的数据展示规则。
- 本地交互数据保存在浏览器 `localStorage` 的 `campus-hui-demo-v1` 键下。个人中心的“清除本地演示数据”可恢复初始状态。
- 待办栏展示偏好与作业完成状态分别保存在 `campus-hui-tasks-visible` 和 `campus-hui-homework` 键下；这些仅是本地界面偏好，不代表真实课程系统。

## 服务端接口预留

`api.js` 是页面数据的唯一访问入口。默认 `CampusAPI` 使用本地模拟数据和浏览器存储；页面组件不直接读写 `localStorage`。接入服务端时，可在加载页面前配置：

```html
<script>
  window.CAMPUS_API_BASE_URL = "https://api.example.com";
</script>
```

同时在 `api.js` 中按需调整请求与服务端响应字段。配置 Base URL 后请求错误会明确显示，不会静默退回演示数据。

| 产品能力 | 当前适配器方法 | 建议接口 |
| --- | --- | --- |
| 校园首页 / 动态列表 | `getHome` / `getPosts` | `GET /home`、`GET /posts?scope=wall` |
| 发布校园动态 / 点赞 | `createPost` / `toggleLike` | `POST /posts`、`POST /posts/{id}/like` |
| 跑腿发布 / 接单 | `createErrand` / `claimErrand` | `POST /errands`、`POST /errands/{id}/claim` |
| 二手发布 / 收藏 | `createListing` / `toggleFavorite` | `POST /listings`、`POST /listings/{id}/favorite` |
| 通知已读 | `markNoticeRead` | `POST /notices/{id}/read` |
| 首页校园论坛 | `getForumThreads` / `createForumThread` | `GET /forum/threads`、`POST /forum/threads` |
| 校园身份认证 | `verify` | `POST /auth/verify` |
| 个人中心 | `getProfile` | `GET /profile` |

真实认证应由服务端与学校授权身份系统对接；客户端不得收集或存储真实学籍凭证、证件信息、密码或支付密钥。跑腿下单、交易沟通、支付、退款和纠纷处理也必须接入可信服务端与合规支付流程后，才可对真实用户开放。

## 后续上线

静态文件可部署至 Vercel、Netlify 或 GitHub Pages，无需构建命令。正式开放给真实学校和用户之前，仍需完成真实 API、身份授权、隐私告知、内容治理、权限校验及安全审查。
